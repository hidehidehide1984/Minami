# 南中チャレンジ 🦉 — アプリ仕様書（再現用）

横浜市立南高等学校附属中学校（南附属中）の **適性検査** 対策のための、小6向け学習Webアプリ。
このドキュメントだけを読めば、別の開発者／AIが同等のアプリを一から再現できることを目的とする。

---

## 0. 重要な前提（必ず守ること）

- 収録する問題は **過去問ではなく、出題傾向に合わせて作るオリジナル練習問題**。画面とドキュメントに「過去問ではない」と明記する。
- 「合格めやす（受験準備度）」は **本番の合格率ではない**。アプリ内の練習データだけから出す“めやす”であることを明記する。
- 4択問題は **キーボード入力なしで解ける**こと（対象が小学生）。記述（作文）だけは入力可とし、自己採点方式にする。

---

## 1. 技術・制約

- **バニラ HTML + CSS + JavaScript のみ**。ビルド不要・フレームワーク不要・サーバー不要。
- `index.html` をブラウザで開くだけで動く（`file://` でも動作）。そのため **ES Modules は使わず**、`<script>` を順番に読み込むだけにする（グローバルに `window.XXX` で公開）。
- データ保存は **ブラウザの localStorage**（端末・ブラウザごとに保存、サーバー送信なし）。
- スマホ／タブレット／PC 対応（モバイル最適化）。日本語UI。
- 公開は **GitHub Pages**（GitHub Actions でデプロイ）。

## 2. データモデル

### 2.1 分野（CATEGORIES）— 8分野
`id: { name, emoji, color }` の連想配列。

| id | name | emoji | 入試での位置づけ |
|----|------|-------|------------------|
| kotoba | ことば・漢字 | 📝 | 適性Ⅰ 言語・語句 |
| dokkai | 読み取り | 📖 | 適性Ⅰ 文章・資料・グラフ |
| kazu | 数と規則 | 🔢 | 適性Ⅱ 数の性質・規則性 |
| zukei | 図形 | 📐 | 適性Ⅱ 面積・体積・角 |
| wariai | 割合・速さ | ⚖️ | 適性Ⅱ 割合・速さ・場合の数 |
| rika | 理科 | 🔬 | 適性Ⅱ 理科 |
| shakai | 社会 | 🗾 | 資料分析・一般常識 |
| shikou | 思考力 | 🧩 | 適性Ⅰ前半 パズル・論理 |

色は分野ごとの識別色（任意の見やすい色でよい）。

### 2.2 問題（QUESTIONS）
すべて4択（`type: "choice"`）。1問は次の形：
```js
{
  id: "kazu03",          // 一意。既存の手作り分は意味ID、自動生成分は "<category>_gNNNN"
  category: "kazu",      // 8分野のいずれか
  level: 1,              // 難易度 1=やさしい / 2=ふつう / 3=チャレンジ
  type: "choice",
  q: "6と8の最小公倍数はいくつ？",
  choices: ["24", "12", "48", "16"], // 4つ。順番はシャッフル
  answer: "24",          // choices のどれか1つと完全一致
  hint: "6の倍数で8でもわり切れる数。",
  exp: "最小公倍数は24。" // 答え合わせ後に出す「かいせつ」
}
```
規約：
- `choices` は必ず**4つ**・**重複なし**・**answer を含む**。
- 数値の答えは文字列（"24", "31.4" など）。表示単位（cm等）は付けず数のみが基本。
- 難易度の目安：1=計算1ステップ/基礎知識、2=2ステップ、3=ひとひねり。
- 規模：8分野合計で **約1940問**（10倍版）。分野バランスはおおよそ 130〜290問/分野。

### 2.3 適性検査チャレンジ（CHALLENGES）— 記述・自己採点
本番形式（長文＋記述／資料＋記述）の**オリジナル**問題。
```js
{
  id: "gomi",
  kind: "Ⅰ",            // "Ⅰ"=読解・記述 / "Ⅱ"=資料・算数理科・記述
  title: "ゴミとリサイクル",
  passage: "ある町の…",   // 読む文章（任意）
  material: "<table class=\"ch-table\">…</table>", // 資料/表（HTML文字列、任意）
  question: "(1)… (2)…",  // 設問
  model: "(1) … \n(2) …", // 模範解答の例（改行可）
  points: ["採点ポイント1", "…"], // 自己採点用チェックリスト
  hint: "ヒント"
}
```
収録：Ⅰ型6問＋Ⅱ型6問＝**12問**。自動採点はできないため、書いたあとに模範解答＋採点ポイントを表示して**自分でまるつけ**する。

### 2.4 学習データ（localStorage の state）
キー：`minami_quiz_progress_v1`。`defaultState()` の構造：
```js
{
  name: "",            // ニックネーム（最大12字）
  xp: 0,               // 経験値
  coins: 0,            // ごほうびコイン
  streak: 0,           // 連続学習日数
  lastStudyDate: "",   // 最後に学習した日 "YYYY-MM-DD"
  studyDates: [],      // 学習した日付一覧
  totalAnswered: 0,    // 4択の総回答数
  totalCorrect: 0,     // 4択の総正解数
  badges: [],          // 取得バッジid
  cat: {},             // 分野別 { kotoba:{seen,correct,recent:[]}, ... }
  items: {},           // 問題別SRS { qid:{box,due,seen,correct,wrong,lastDate} }
  dailyGoal: 30,       // 1日の目標問題数（既定30）
  todayCount: 0,       // 今日解いた数
  todayDate: "",       // todayCount を数えている日付
  dailyCounts: {},     // 日別の実施数 { "2026-06-19": 12 }
  dailyCorrect: {},    // 日別の正答数 { "2026-06-19": 9 }
  examDate: "2027-02-03", // 受験日（固定）
  challengeDone: {},   // 適性検査チャレンジで完了した { id: true }
  charmUsedMonth: "",  // ストリークおまもりを使った月 "YYYY-MM"（月1回）
  comeback: false,     // お休み後に復帰したことがある（おかえりバッジ用）
  goalV2: true         // 目標30への移行フラグ（内部用）
}
```
`loadState()` の挙動：
1. 保存値を読み、`defaultState()` に**ない不足キーを補完**（バージョン違い対策）。
2. 8分野の `cat` レコードを初期化。
3. **`examDate` は常に固定値で上書き**（"2027-02-03"）。
4. **目標問題数の一度きりの移行**：`goalV2` が無ければ `dailyGoal=30` にして `goalV2=true`。
5. `todayDate` が今日でなければ `todayCount=0` にリセット。

ユーティリティ：
- `todayStr(d?)` → "YYYY-MM-DD"（ローカル時刻）。
- `daysBetween(a,b)` → 日数差（整数）。
- `saveState` / `loadState` / `resetState`。

## 3. 出題ロジック（adaptive.js）

固定の難易度順ではなく、**適応出題**（各問にスコアを付け最高点の1問を選ぶ）。

- `BOX_INTERVAL_DAYS = [0,1,2,4,7,14]`（Leitnerの箱→次に出すまでの日数）。
- **分野の正答率** `categoryAccuracy`：直近結果（最大10件）が3件以上あれば `直近平均*0.7 + 全体*0.3`、なければ `correct/seen`、データなしは 0.5。
- **狙う難易度** `targetLevel`：`seen<3 || acc<0.5 → 1` ／ `acc<0.8 → 2` ／ それ以上 → 3。
- **次の1問** `pickNextQuestion(state, {avoidId, recentCats})`：全問にスコア付与、最高点を選ぶ。
  - 苦手分野優先：`+ (1-acc)*35`
  - 既出問題：今日既出なら `-45`／復習期限 overdue≥0 なら `+25 + min(overdue,7)*4`、未到来なら `-25`／箱が低いほど `+(5-box)*3`
  - 未出題：`+28`
  - 難易度一致：`- |level - targetLevel| * 9`
  - インターリーブ（直近分野を避ける）：直近に出た分野ほど `- (距離)*12`
  - ゆらぎ：`+ random*14`
- **回答の記録** `recordAnswer(state,q,correct)`：分野成績更新（recentは末尾10件）、問題のSRS更新（正解で box+1・最大5、不正解で box=0、`due = 今日 + BOX_INTERVAL_DAYS[box]`）、`totalAnswered/Correct` 更新。
- `weakestCategory(state)`：seen≥3 の中で正答率最小の分野（ホームの苦手アドバイス用）。

「分野をえらんで練習」時は、その分野内で「復習期限＋箱の低さ＋ランダム」で選ぶ簡易版（`chooseFromPool`）。

## 4. やる気の仕組み（gamify.js）

- **レベル/XP**：`levelFromXp = floor(xp/100)+1`、`xpInLevel = xp%100`（100XPごとに1レベル）。
- **XP付与**（app.js側）：4択正解 `+ (10 + (level-1)*5)` XP・`coins += level`／不正解 `+2` XP（前向きメッセージ＋「復習リストに入れたよ」表示）。チャレンジ**初回**完了 `+25` XP・`coins+3`（`dailyCorrect` にも+1）／完了済みの再「できた」は `+5` XP のみ（報酬の稼ぎ直し防止）／「もう一度」`+8` XP。
- **連続日数 streak** `updateStreak`：その日初学習で、前日も学習なら+1、間が空けば1へリセット、初回は1。`studyDates` に追加。
  - **ストリークおまもり（月1回の救済）**：ちょうど1日だけ休み（gap=2）かつ streak≥2 かつ当月未使用なら、リセットせず+1して `charmUsedMonth` に当月を記録。戻り値 `{charmUsed}` を返し、UI は「🛡おまもりが守ってくれたよ」と通知。
  - 2日以上休みでリセットする際、直前 streak≥3 なら `comeback=true`（おかえりバッジ用）。
- **デイリーミッション**：今日 `todayCount / dailyGoal` 問。**目標にちょうど達した直後**の「つぎの問題」で、モーダル「今日はここまで🎉／あと3問だけ／まだつづける！」を出す（やめどきを作る。「あと3問」は消化後に再度モーダル）。
- **バッジ（14種）** `BADGES`：各 `{id,name,emoji,desc,check(state)}`。
  - first(1問), correct10/50/100(正解数), streak3/7/30(連続), goal(今日の目標達成), level5(Lv5=400XP), explorer(全8分野に挑戦), writer(チャレンジ初挑戦), today3(1日に3問), writer3(チャレンジ3問完了), comeback(お休み後の復帰)。
  - `checkNewBadges` は未取得で条件成立したものを付与し返す（取得時ポップアップ）。

### 合格めやすメーター（受験準備度）`readiness(state)` → 0〜100
※本番合格率ではない。5要素の加重和×100：
```
score = round( (acc*0.30 + weakest*0.25 + coverage*0.20 + volume*0.15 + consistency*0.10) * 100 )
```
- `acc` = totalCorrect/totalAnswered（無回答は0）
- `practiced` = seen≥5 の分野、`coverage` = practiced数/8
- `volume` = min(totalAnswered/200, 1)
- `weakest` = practiced内の最小正答率 × (practiced数/8)  ※全分野やってこそ満点
- `consistency` = min(直近14日で学習した日数/10, 1)

ステージ閾値：0/20/40/60/75/90 →「🌱スタート／📗きほんづくり／📈のびざかり／🔥じっせん力アップ／🌟合格圏が見えた／👑合格まであと一歩」。
アドバイス：総回答<10なら「色々試そう」、未練習分野があればそこへ誘導、なければ最弱分野へ誘導（90以上は仕上げの復習）。

成績画面の末尾に **「👨‍👩‍👧 おうちの方へ」**カード：既存データから「今週◯日学習」「連続◯日（継続をほめて）」「得意分野」「伸ばしどころ分野」を自動文章化。

### モーダル
- バッジ獲得ポップアップ、**目標達成モーダル**（今日はここまで／あと3問だけ／まだつづける）、設定（なまえ／1日の目標問題数／受験日は固定表示／データリセット）、トースト通知。

### 解答処理の要点（app.js）
- 4択は `userInput === answer` で判定。
- 答え合わせ→ `Adaptive.recordAnswer` →XP/コイン→ `todayCount`・`dailyCounts(+1)`・`dailyCorrect(+1 if 正解)` →`updateStreak`→バッジ判定→保存→演出。
- **Enter誤作動対策**：記述入力Enterで `preventDefault`、答え合わせ直後350msは「つぎ」ボタンの作動を無視（解説を読まず飛ばさない）。

### 適性検査チャレンジの統合
- 一覧から個別に解ける。
- 「今日の問題」中は **6問ごとに1問**チャレンジを自動挿入（`CHALLENGE_EVERY=6`）。未完了を優先、直前と同じものは避ける。採点後は自動でクイズに復帰。スキップ導線あり。
- 完了で `challengeDone[id]=true`、日別記録・ストリーク・XP に反映（分野別正答率 `cat` には加算しない＝合格めやすの土台は自動採点ドリルから算出）。

## 6. 問題の作り方（最重要・再現の肝）

**正確さ最優先。** 大量生成では「答えが必ず正しい」ことを機械的に保証する。

### 6.1 計算系（kazu / zukei / wariai / shikou / dokkaiの数値）
- **答えはプログラムで厳密計算**し、テンプレート＋パラメータ掃引で大量生成。
- 例テンプレ：
  - 数：等差/等比数列のk番目、倍数の個数 `floor(N/m)`、最小公倍数/最大公約数、余り `N%m`、和 `N(N+1)/2`、平方数・三角数、約数の個数、偶数のk番目。
  - 図形：正方形/長方形/三角形/平行四辺形/台形の面積、周、立方体/直方体の体積・表面積、円の面積 `r*r*3.14`・円周 `d*3.14`、多角形の内角の和 `(n-2)*180`・正多角形の1角。
  - 割合・速さ：`X円のP%`、P割引、速さ×時間・道のり÷速さ、食塩水の濃度、比の分配、利益と定価。
  - 思考力：つるかめ算 `kame=(legs-2*total)/2`、植木算（両端）`D/g+1`、逆算、曜日（mod 7）、時計の角度、仕事算、年齢算、差が増える数列。
  - 資料読み取り：日別データ表（最多/合計/平均/差）、割合%、円グラフ中心角 `pct*3.6`、所持金で最大何個、接続語。
- **誤答（ダミー）の作り方**：ありがちな誤り（計算順ミス／÷2忘れ／半径と直径の取り違え／単位の桁違い／答え±少し）。`answer` と重複しない一意な3つを選び、4択をシャッフル。

### 6.2 知識系（kotoba / rika / shakai）
- **正確なデータ表**から生成（事実誤りを避けるため、確実に正しいものだけ）。
  - ことば：漢字の読み、対義語、類義語、ことわざ/四字熟語の穴うめ、慣用句（体の部分）、主語・述語（文の組み合わせ）。読み/対義語などの誤答は「他の語の正解」をダミーに流用。
  - 理科：基礎事実バンク（q,正解,誤答3,難易度）。さらに「項目を問題文に明示」して個別問題化（例：『鉄くぎ・木・ガラス・ゴム』のうち電気を通すものは？ → 金属/磁石/金属判定）。
  - 社会：47都道府県の「県庁所在地」「地方区分」表から自動生成（誤答は他の都市/地方）＋公民・地理の事実バンク。

### 6.3 生成後の必須検証（自動）
全問について：`type==="choice"` ／ `choices.length===4` ／ `choices` 重複なし ／ `answer ∈ choices` ／ **id重複なし** ／ 問題文（q）重複なし。1件でも違反したら生成失敗とみなす。

### 6.4 既存資産の保持
- 既存の手作り問題ID（例 `kazu03`）は維持し、自動生成分は `"<category>_gNNNN"` で採番（学習記録 `items` のIDが壊れないように）。

## 7.5 バックアップ＆クラウド同期（cloudsync.js）

### バックアップ（ネット不要）
- 設定画面から記録JSONをファイルに**書き出し**（`minami-kiroku-YYYY-MM-DD.json`）／**読み込み**。
- 読み込みは上書きではなく `mergeStates` で**合成**する。

### マージ規則 `mergeStates(a, b)`（クラウド同期と共用・順序対称）
- xp / coins / totalAnswered / totalCorrect / streak → **大きい方**
- badges / studyDates / challengeDone → **和集合**
- dailyCounts / dailyCorrect → **日付ごとに大きい方**
- cat（分野別成績）→ 分野ごとに **seen が大きい方**
- items（問題別SRS）→ 問題ごとに **lastDate が新しい方**（同日なら seen が大きい方）
- todayCount/todayDate → 同日なら大きい方、違う日なら**新しい日**のもの
- name/dailyGoal はローカル優先、comeback/goalV2 は OR、charmUsedMonth は新しい月

### クラウド同期（Firebase Firestore REST・SDK不使用）
- 設定：`js/firebase-config.js` の `window.FIREBASE_CONFIG = { apiKey, projectId }`。**空なら同期UIは「未設定」表示のみで、アプリは完全にオフライン動作**。
- 識別：**同期コード**（`minami-` + 紛らわしい文字を除いた英数12字、`crypto.getRandomValues` 生成）。localStorage の別キー `minami_sync_code` に保存（stateには含めない）。
- 保存先：`projects/{projectId}/databases/(default)/documents/progress/{同期コード}` に
  `{ data: stringValue(JSON全体), updatedAt: integerValue }` の1ドキュメント。REST を `?key=apiKey` 付き fetch で GET / PATCH。
- 同期タイミング：**起動時**に pull→merge→setState→push。**保存のたび**（`Store.saveState` をラップ）3秒デバウンスで push。失敗は静かに無視（オフライン優先）。
- 設定画面UI：未設定→案内文のみ／未接続→「☁️新しくはじめる」「🔑コードを入力」／接続中→コード表示・最終同期時刻・「🔄いますぐ同期」「同期をやめる」。
- セキュリティ：Firestoreルールで `progress/{code}` の get/create/update のみ許可（`data` は string・300KB未満に制限）、**list/delete 禁止**。コードが実質のパスワード。個人情報はニックネームのみ。
- セットアップ手順は `SETUP_FIREBASE.md`（プロジェクト作成→Firestore作成(asia-northeast1)→ルール貼り付け→apiKey/projectId取得→config記入）。

## 8. デプロイ（GitHub Pages）
- 静的サイトなので、リポジトリのサブフォルダをそのまま公開。
- GitHub Actions（`actions/configure-pages` → `upload-pages-artifact`(path=アプリフォルダ) → `deploy-pages`）で、対象ブランチへ push するたび自動デプロイ。
- 初回のみ Settings → Pages → Source を「GitHub Actions」にする必要がある（トークンでは自動有効化できないため）。
- URL 形式：`https://<ユーザー名>.github.io/<リポジトリ名>/`。
